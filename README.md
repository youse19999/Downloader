# Rust + egui 動画ダウンローダー設計計画

## 1. 目的とスコープ

`yt-dlp` を外部プロセスとして起動し、URL で指定された動画をユーザーが選んだ保存先へダウンロードするデスクトップアプリを設計する。初期リリースは単一 URL の取得に限定する。

### 初期リリースの必須機能

- URL の入力と基本検証
- 保存先ディレクトリの選択
- `yt-dlp` の起動、進捗表示、終了結果の通知
- 実行中ジョブのキャンセル
- `yt-dlp` 未導入やダウンロード失敗の説明表示

### 初期リリース対象外

- プレイリストおよび複数 URL
- 複数ジョブの同時実行・キュー
- 動画・音声形式の詳細選択
- `yt-dlp` の自動更新・自動導入
- ダウンロード履歴とリトライ

## 2. 要件と設計前提

### 機能要件

| ID | 優先度 | 要件 |
|---|---|---|
| FR-01 | 必須 | URL を入力し、ダウンロードを開始できる |
| FR-02 | 必須 | 保存先ディレクトリを指定できる |
| FR-03 | 必須 | 待機・起動中・実行中・完了・失敗・キャンセルの状態を表示する |
| FR-04 | 必須 | 取得できる場合、進捗率・速度・ETA を表示する |
| FR-05 | 必須 | 実行中ジョブをキャンセルできる |
| FR-06 | 必須 | `yt-dlp` の起動失敗と非ゼロ終了を区別して表示する |
| FR-07 | 推奨 | 保存先と実行ファイルの設定を再起動後も保持する |

### 品質要件

- **応答性:** プロセス起動、出力読み取り、終了待ちは UI スレッド上で行わない。
- **安全性:** URL やパスをシェル文字列に連結せず、コマンド引数として個別に渡す。
- **失敗の可視性:** 起動失敗、非ゼロ終了、キャンセル、出力解析不能を区別する。
- **テスト容易性:** UI、プロセス制御、進捗解析を分離し、プロセス実行を差し替え可能にする。
- **保守性:** yt-dlp の出力形式への依存をプロセスアダプター内に閉じ込める。

### 仮定

- 初期リリースでは `yt-dlp` をユーザーが別途インストールする。
- 一度に実行するジョブは 1 件とする。
- 出力テンプレートは `%(title)s [%(id)s].%(ext)s` とする。
- 対象 OS と最小バージョンは未確定。ファイルダイアログ、プロセス終了、配布方式は OS 決定後に検証する。

## 3. ドメインモデルと状態遷移

### モデル案

```rust
struct DownloadRequest {
    url: Url,
    output_dir: PathBuf,
}

enum DownloadState {
    Idle,
    Starting,
    Running(DownloadProgress),
    Cancelling,
    Completed(DownloadResult),
    Failed(DownloadFailure),
    Cancelled,
}

struct DownloadProgress {
    percent: Option<f32>,
    downloaded_bytes: Option<u64>,
    total_bytes: Option<u64>,
    speed_bytes_per_sec: Option<f64>,
    eta_seconds: Option<u64>,
}

struct DownloadResult {
    output_path: Option<PathBuf>,
}
```

URL は開始前に解析・検証し、検証済み値を `DownloadRequest` に格納する。`percent` は `0.0..=100.0` に制約し、yt-dlp が値を報告しない場合は `None` とする。UI は不明値を推定しない。

### 状態遷移

```text
Idle ──開始──> Starting ──起動成功──> Running
                  │                      ├─終了コード 0──> Completed
                  │                      ├─終了コード 非0─> Failed
                  │                      └─キャンセル要求─> Cancelling
                  └─起動失敗──> Failed                         │
                                                             └─終了確認──> Cancelled
```

- `Starting` または `Running` 中の開始操作は拒否する。
- 完了・失敗・キャンセル後に再実行できる。
- キャンセル要求後、子プロセスの終了を確認してから `Cancelled` にする。
- キャンセルと正常終了が競合した場合、観測したプロセス終了結果を記録する。

## 4. モジュールと依存境界

```text
src/
├── main.rs
├── app/
│   ├── mod.rs
│   └── view_model.rs
├── download/
│   ├── mod.rs
│   ├── model.rs
│   ├── service.rs
│   ├── process.rs
│   ├── progress_parser.rs
│   └── error.rs
└── settings.rs
```

| モジュール | 所有する責任 | 依存 |
|---|---|---|
| `app` | egui 描画、入力取得、状態に応じた操作可否、イベント反映 | `download::model`、サービス境界 |
| `download::model` | リクエスト、進捗、結果、状態の型と不変条件 | 標準ライブラリ中心 |
| `download::service` | ジョブ開始、イベント配信、キャンセル制御 | `process`、モデル |
| `download::process` | yt-dlp 起動、stdout/stderr 処理、終了コード取得 | `std::process`、進捗パーサー |
| `download::progress_parser` | 出力行を進捗イベントに変換 | モデル |
| `download::error` | アプリ内エラー分類と表示用要約 | モデル |
| `settings` | 保存先・実行ファイル設定の読み書き | 設定保存ライブラリ |

依存方向は `app → service → process` とする。`process` は egui 型を参照しない。初期版では不要な抽象階層を設けず、プロセス実行差し替えに必要な境界に限定する。

## 5. プロセス実行契約

### 起動コマンド

```text
yt-dlp
  --newline
  --progress
  --output <output_dir>/%(title)s [%(id)s].%(ext)s
  <validated_url>
```

- URL、保存先、テンプレートをシェルコマンド文字列に連結しない。
- `Command::arg` / `args` で引数を渡し、シェルを介さない。
- 保存先は `PathBuf` として扱い、パス区切りを手動連結しない。
- ファイル名衝突時は初期版では yt-dlp の既定動作に従う。変更可能にする場合は明示的な設定と契約を追加する。

### stdout / stderr

両ストリームを継続して読み取る。片方だけを読むと、未読側のパイプバッファが満杯になり子プロセスが停止する可能性がある。

1. ワーカーが子プロセスを所有する。
2. stdout と stderr をそれぞれ読み取る。
3. 進捗行を解析し、最新値をイベントで通知する。
4. stderr の診断行は上限付きで保持する。
5. 終了コードを確認し、成功・失敗を決める。

成功判定は終了コード `0` を基準とし、出力テキストから推測しない。

### 進捗形式

通常出力の解析と `--progress-template` による機械可読形式を比較する。

| 方式 | 利点 | 代償 |
|---|---|---|
| 通常の進捗行 | 追加オプションが少ない | 表示形式・バージョン差に影響されやすい |
| `--progress-template` | パーサーの契約を固定しやすい | 対応バージョンを定義し実出力を検証する必要がある |

**推奨:** 対応バージョンを定義し、`--newline` と `--progress-template` を使う。未知形式は致命的エラーにせず、進捗不明としてダウンロードを継続する。テンプレートの実出力とバージョン互換性は実装時に確認する。

## 6. 並行性、イベント、キャンセル

- UI スレッドは egui 更新と状態描画を担当する。
- ジョブごとにワーカースレッドを起動する。
- ワーカーから UI へチャネルでイベントを送り、UI はフレーム更新時に受信キューを処理する。
- 起動には `DownloadRequest`、キャンセルには専用制御チャネルまたは cancellation token を使う。
- ワーカーが `Child` の唯一の所有者となり、UI から直接プロセスを操作しない。
- キャンセル要求後は対象 OS で検証した方法で子プロセスを終了し、終了を待つ。
- yt-dlp が子プロセスを生成する場合、子孫プロセスも停止するかを OS ごとに検証する。
- UI 終了時はキャンセルを要求し、プロセス終了を待ってからアプリを閉じる方針とする。

`Child::kill` はプロセスツリー全体の終了を保証しない。子孫を含む停止が必須なら OS 固有実装または専用クレートを評価する。

## 7. エラー契約

```rust
enum DownloadFailure {
    InvalidUrl,
    InvalidOutputDirectory,
    ExecutableNotFound,
    SpawnFailed(std::io::Error),
    StreamReadFailed(std::io::Error),
    ProcessExited {
        code: Option<i32>,
        diagnostic_tail: String,
    },
    InternalChannelClosed,
}
```

- 入力エラーはプロセス起動前に検出し、該当フィールド付近に表示する。
- 実行ファイル不在と権限・OS 起因の起動失敗を区別する。
- yt-dlp の非ゼロ終了は終了コードと stderr 末尾を診断情報として保持する。
- UI では短い説明を表示し、詳細診断は必要時に開けるようにする。
- stderr 保持量に上限を設け、長時間実行時のメモリ増加を防ぐ。
- 進捗解析失敗はプロセス失敗と混同しない。
- URL に認証情報やクエリトークンが含まれる可能性を考慮し、通常ログへ URL 全体を出さない。

## 8. UI と設定

- URL 入力欄
- 保存先選択と現在値の表示
- yt-dlp 実行ファイル設定（既定は `PATH` 検索）
- 状態に応じた開始・キャンセル操作
- 状態、進捗率、速度、ETA の表示
- 完了時の保存先表示
- 失敗時の要約と折りたたみ可能な診断情報

`Starting` / `Running` 中は URL と保存先を固定し、二重起動を防ぐ。設定保存を初期リリースに含める場合、保存するのは保存先と実行ファイルパスに限定し、URL や認証情報を履歴保存しない。

## 9. 依存候補

採用時にバージョン、ライセンス、対象 OS 対応を確認する。

- GUI: `eframe` / `egui`
- URL 検証: `url`
- ファイルダイアログ: `rfd`
- 設定保存: `serde` と `directories` 系クレート
- ログ: 必要に応じて `tracing`
- キャンセル通知: 標準チャネル、または軽量な cancellation クレート

初期版では非同期ランタイムを導入せず、スレッドとチャネルで egui 更新ループと連携する。複数同時ジョブや複数ストリーム処理が必要になった時点で Tokio の採否を評価する。

## 10. 検証計画

### 単体テスト

- URL の受理・拒否条件
- 保存先の存在・書き込み可能性
- 状態遷移の許可・拒否
- 進捗テンプレートの正常行、欠落値、不正値、未知行の解析
- stderr 診断末尾のサイズ上限
- 空白、引用符、特殊文字を含む URL・パスでの引数構築

### プロセス契約テスト

実 yt-dlp に依存しない偽実行ファイルまたは差し替え可能な runner を使い、次を検証する。

- 実行ファイル不在が `ExecutableNotFound` になる。
- 起動失敗と非ゼロ終了が異なるエラーとして伝わる。
- stdout と stderr の同時出力でデッドロックしない。
- キャンセル後、終了確認を経て `Cancelled` になる。
- 未知の進捗形式でも終了判定が正しく行われる。
- UI スレッドがプロセス完了待ちをしない。

### 手動・実環境確認

- 対応 OS ごとのファイルダイアログとパス処理
- 実 yt-dlp バージョンにおける進捗テンプレート出力
- 成功、通信エラー、制限付き動画、保存先権限エラー
- キャンセル時のプロセスおよび子孫プロセス終了
- アプリ終了時のジョブ処理

本節は検証計画であり、実施済み結果ではない。

## 11. 設計判断（ADR）

### ADR-001: UI とプロセス実行を分離する

- **決定:** egui は状態表示と操作に限定し、外部プロセスはワーカーが管理する。
- **根拠:** プロセス操作が UI フレームを塞ぐことを防ぐ。
- **代償:** イベント配送と状態同期が必要。
- **検証:** 長時間実行や大量出力でも UI が応答し、イベント順序が状態遷移と整合すること。

### ADR-002: yt-dlp を外部依存として扱う

- **決定:** 初期版では自動導入・更新せず、設定済み実行ファイルまたは `PATH` 上の yt-dlp を使う。
- **根拠:** 配布、更新、署名、OS 別バイナリ管理を初期スコープから外す。
- **代償:** 利用者にインストール手順が必要。
- **再評価条件:** 配布要件または利用状況が同梱を求める場合。

### ADR-003: 進捗解析をアダプター境界に置く

- **決定:** yt-dlp 出力形式への依存を `progress_parser` に閉じ、解析失敗とプロセス失敗を分離する。
- **根拠:** 出力変更の影響を局所化する。
- **代償:** 対象バージョンと出力契約の管理が必要。
- **検証:** 対応バージョンの出力サンプルを契約テストに固定する。

## 13. Windows 向け実装とビルド

### 開発環境

- Rust stable toolchain
- Windows 10/11 x64 を想定
- MSVC C++ Build Tools（Windows 用 Rust target のリンクに必要）
- 実行時に `yt-dlp.exe` を PATH に配置するか、画面で実行ファイルのパスを指定する

### ローカルビルド

```powershell
cd downloader
cargo build --release --target x86_64-pc-windows-msvc
```

生成物は `target\x86_64-pc-windows-msvc\release\downloader.exe`。

### ZIP 配布

`.github/workflows/windows-release.yml` は GitHub Actions の Windows runner で x64 MSVC ビルドを行い、`downloader.exe` と README を `downloader-windows-x64.zip` にまとめる。手動実行または `v*` タグ push で workflow を起動し、Actions の artifact から ZIP を取得する。

配布 ZIP には yt-dlp 本体を含めない。利用者は別途 yt-dlp を導入する必要がある。
